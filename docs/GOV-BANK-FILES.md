### รูปแบบ V2.0 (ค่าเริ่มต้น) — ตรงสเปก
- ข้อความ **UTF-8** (ไม่มี BOM) คั่นด้วย `|` ไม่มี `|` หัว/ท้ายบรรทัด ขึ้นบรรทัดด้วย **CRLF**
- ห้ามมีอักขระ `* + / \ ! $ % # & @ , ' "` → ระบบตัดออกให้ (`/` ในบ้านเลขที่ แปลงเป็น `-` เช่น 12/3 → 12-3)
- **Header (H) 22 ช่อง**: `H|SENDER_ID(0000)|เลขผู้เสียภาษีผู้นำส่ง|สาขา 6 หลัก|1|PND1 หรือ PND1A|เลขผู้หักภาษี|สาขา|ชื่อแผนก|LTO 0|เดือน 01–12 (1ก = 00)|ปี พ.ศ.|ประเภทสาขา|00 ยื่นปกติ/01… เพิ่มเติม|จำนวนราย|รวมเงินได้|รวมภาษี|เงินเพิ่ม 0.00|รวมภาษี+เงินเพิ่ม|เงินโอน|UserID|2 (อินเทอร์เน็ต)`
- **Detail (D) 26 ช่อง**: `D|ลำดับ|สาขา|PIN 13 หลัก|TIN 0000000000|คำนำหน้า|ชื่อ|ชื่อสกุล|ววดดปปปป (พ.ศ.; 1ก = 3112ปปปป)|อัตราภาษี 0.00|เงินได้|ภาษี|ประเภทเงินได้ 1=40(1)|เงื่อนไข 1/2/3|อาคาร|ห้อง|ชั้น|หมู่บ้าน|เลขที่|หมู่|ซอย|ถนน|ตำบล|อำเภอ*|จังหวัด*|รหัสไปรษณีย์*`
- จำนวนเงินทศนิยม 2 ตำแหน่ง ปัดแบบสากล (หลักที่ 3 ≥ 5 ปัดขึ้น) — ใช้การปัดแบบจำนวนเต็มสตางค์ (ไม่มีปัญหา 1.005 → 1.00)
- ชื่อไฟล์: `PND1_{เลขผู้เสียภาษี13}_{สาขา6}_{ปี พ.ศ.}_{เดือน}_{ประเภทการยื่น}_{ครั้งที่ส่ง}.txt` เช่น `PND1_0115560012342_000000_2569_09_00_00.txt`
- เงื่อนไขการหักภาษี: 1 = หัก ณ ที่จ่าย, 2 = ออกให้ตลอดไป (พนักงานที่ตั้ง "นายจ้างออกภาษีให้"), 3 = ออกให้ครั้งเดียว
- การตรวจสอบ: เลขผู้เสียภาษีบริษัทและพนักงาน 13 หลัก + หลักตรวจสอบ (mod 11 — `validNationalId`), เลขสาขาเป็นตัวเลข ≤ 6 หลัก,
  คำนำหน้า/ชื่อ/สกุลครบ, เงินได้/ภาษีไม่ติดลบ, ภาษี ≤ เงินได้, เลขไม่ซ้ำ, (V2.0) อำเภอ/จังหวัด/รหัสไปรษณีย์ครบ

### รูปแบบ V1.0 (PND1.txt) — ตรงสเปก
20 ช่องคั่นด้วย `|` ชื่อไฟล์ต้องเป็น `PND1.txt` วันที่ `DDMMYYYY` พ.ศ., เดือน 1ก = `00`, TIS-620 — สำหรับ WHT SVS / SWC รุ่นเก่า

### วิธียื่น (e-Filing)
1. รายงาน › ภ.ง.ด.1 เลือกเดือน (หรือแท็บ ภ.ง.ด.1ก เลือกปี) › ถ้ามีหลายสาขาภาษี ให้เลือกสาขาแล้วยื่นแยกตามเลขที่สาขา
2. เลือกรูปแบบ "สรรพากร ฟอร์แมตกลาง V2.0" › **ตรวจข้อมูลและสร้างไฟล์** › แก้ข้อมูลตามรายการข้อผิดพลาด (ถ้ามี) › ดาวน์โหลด
3. เปิดโปรแกรม **WHT Software Component (SWC)** ของกรมสรรพากร (รุ่น 1.5.4 ขึ้นไป) นำเข้าไฟล์ .txt ตรวจยอด แล้วสร้างไฟล์ยื่น (.rdx)
   — หรือใช้ **RD Prep**: เมนูโอนย้ายข้อมูล › ภ.ง.ด.1 › เลือกไฟล์รูปแบบ "RD Prep" › แบ่งข้อมูลด้วยสัญลักษณ์ `|` › วันที่ dd/mm/yyyy พ.ศ. (มีสัญลักษณ์)
   › ลากช่อง 0–10 ตามลำดับ (ลำดับที่, เลขประจำตัว, สาขา, คำนำหน้า, ชื่อ, สกุล, เงินได้ตามมาตรา, วันที่จ่าย, เงินได้, ภาษี, เงื่อนไข) › โอนย้าย › บันทึก .rdx
4. เข้า https://efiling.rd.go.th › ยื่นแบบ › ภ.ง.ด.1 (หรือ 1ก) › ยื่นแบบโดยการอัปโหลดไฟล์ › เลือกไฟล์ .rdx › ตรวจยอดตรงกับหน้า "แบบ ภ.ง.ด.1" ที่พิมพ์ › ยืนยันและชำระภาษี
5. ภ.ง.ด.1ก: ดาวน์โหลดไฟล์ "ข้อมูลกองทุน" แนบด้วย เพื่อให้เงินสมทบประกันสังคม/กองทุนสำรองเลี้ยงชีพแสดงใน My Tax Account ของพนักงาน

> e-Withholding Tax (ยื่นผ่านธนาคาร) ใช้กับ ภ.ง.ด.3/53/54 เป็นหลัก ไม่เปลี่ยนวิธียื่น ภ.ง.ด.1 ของนายจ้าง; สิ่งที่เปลี่ยนคือภาคบังคับยื่นอิเล็กทรอนิกส์ (ปีภาษี 2567+) และ SWC 1.5.4 (ก.ค. 2568)

### วิธีใช้
1. ตั้งค่า › ตั้งค่าเวลา / เงินเดือน / ภาษี › บัญชีบริษัทและไฟล์โอนเงิน: ธนาคาร, เลขที่บัญชี, รหัสสาขา, **Company ID**, ชื่อผู้โอน, รูปแบบไฟล์เริ่มต้น
2. งวดเงินเดือน › เปิดงวดที่อนุมัติแล้ว › **ไฟล์โอนธนาคาร** › เลือกรูปแบบ › ตรวจ/แก้บัญชีบริษัทและวันที่มีผล › ตรวจข้อมูลและดูตัวอย่างไฟล์ › ดาวน์โหลด
3. อัปโหลดในระบบธนาคาร (K BIZ / SCB Business Anywhere / BIZ iBanking / Krungthai Corporate Online / Krungsri Biz Online / ttb business one)
   เมนู Payroll/Direct Credit › Upload file › ตรวจจำนวนรายการและยอดรวมให้ตรงกับหน้าต่างตรวจไฟล์ › อนุมัติรายการตามสิทธิ์ผู้อนุมัติของบริษัท
4. **ครั้งแรก**: ส่งไฟล์ตัวอย่างให้เจ้าหน้าที่ Cash Management ของธนาคารตรวจ หรือทดลองโอนรายการเดียวก่อน

## 5. ปรับรูปแบบไฟล์เมื่อสเปกของธนาคาร/หน่วยงานต่างไป (ไม่ต้องแก้โปรแกรม)

ตั้งค่า › **รูปแบบไฟล์** (`/settings/file-formats`; ลิงก์จากหน้า งวดเงินเดือน, ภ.ง.ด.1, สปส.1-10 และหน้าต่างไฟล์โอนธนาคาร)

1. เลือกแท็บ (ธนาคาร / สปส.1-10 / ภ.ง.ด.1 / ภ.ง.ด.1ก / ข้อมูลกองทุน) › เลือกรูปแบบที่ใกล้เคียง › **คัดลอกไปแก้ไข**
2. แก้ทั้งไฟล์: ชื่อ, ชนิด (ความยาวคงที่ / มีตัวคั่น), ตัวคั่น, การเข้ารหัส (TIS-620 / UTF-8 / UTF-8+BOM), ขึ้นบรรทัด (CRLF/LF), รูปแบบชื่อไฟล์ `{ตัวแปร}`,
   ผู้รับที่รวม (ทุกธนาคาร / ธนาคารเดียวกัน / ต่างธนาคาร), การตรวจจำนวนหลักเลขบัญชี
3. แก้ช่องในส่วนหัว / รายการ / ส่วนท้าย: ชื่อช่อง, ข้อมูลจาก (ตัวแปรจากรายการคงที่ เช่น `employee.national_id`, `entry.net_pay`, `company.tax_id`,
   `batch.effective_date`, ค่าคงที่, ว่าง, ลำดับที่), ชนิด (ข้อความ / ตัวเลขล้วน / จำนวนเต็ม / จำนวนเงินมีจุด / จำนวนเงินเป็นสตางค์ / วันที่),
   ความยาว (ไฟล์ความยาวคงที่ = **ไบต์**), ชิดซ้าย/ขวา, เติมช่องว่าง/0, รูปแบบวันที่ (`DDMMYYYY`, `DD/MM/YYYY`, `YYYYMMDD`, `MMYY` …) และ พ.ศ./ค.ศ.,
   ต้องมีค่า — เลื่อนขึ้น/ลง/ลบ/เพิ่มช่องได้ ตำแหน่งเริ่ม–สิ้นสุดคำนวณให้อัตโนมัติ
4. ดู **ตัวอย่างไฟล์จากข้อมูลจริง** ของงวดที่เลือก (8 บรรทัดแรก, จำนวนไบต์ต่อบรรทัด, รายการข้อผิดพลาด) › ดาวน์โหลดตัวอย่างส่งให้ธนาคารตรวจ
5. **บันทึกรูปแบบ** › กด **ใช้เป็นค่าเริ่มต้น** เพื่อให้หน้าส่งออกเลือกให้อัตโนมัติ

รูปแบบที่ปรับเองเก็บในตาราง `file_formats` (migration `20261008120000_file_formats.sql`, RLS: ดูได้เมื่อมีสิทธิ์ payroll/report/settings view,
แก้ได้เมื่อมีสิทธิ์ payroll edit หรือ settings edit, บันทึก Back Log) — รูปแบบในระบบ (built-in) แก้ไม่ได้ จึงกลับไปใช้ต้นฉบับได้เสมอ

## 6. สำหรับนักพัฒนา

- เพิ่มรูปแบบในระบบ: เพิ่ม `FileLayout` ใน `lib/payroll/file-layouts.ts` (ระบุ `status` และ `source` = URL + วันที่) แล้วเพิ่มบรรทัดทดสอบที่คาดหวังใน `tests/payroll-files.test.ts`

- TIS-620: `encodeTis620` (U+0E01–U+0E3A → 0xA1–0xDA, U+0E3F–U+0E5B → 0xDF–0xFB), อักขระนอกตารางแทนด้วยตัวใกล้เคียง/`?`;
  `truncateBytes` ตัดโดยไม่แยกสระ/วรรณยุกต์ออกจากพยัญชนะ
